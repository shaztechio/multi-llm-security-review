# Security review

Reviewed the repository defensively on September 30, 2026. Six findings were identified: three were fixed in the executable scripts (known credential inheritance, unsafe report/artifact link handling, and sensitive progress output), and three remain in the active reusable workflow because files under `.github/workflows/` must not be modified. Equivalent credential-persistence and raw-artifact issues were corrected in the archived workflow template outside that protected directory. No hard-coded real API keys, direct shell interpolation of the model prompt, unsafe executable deserialization, application authentication endpoints, insecure cryptographic implementation, or repository-owned HTTP request handlers were found. This is a source review, not a guarantee of safe execution on an untrusted repository or an audit of the external agent CLIs.

## Coverage

The initial inventory used `rg --files --hidden -g '!.git/**'`, `Get-ChildItem -Force`, and a recursive search for `AGENTS.md`; no repository instruction files were present. All 14 original tracked files were enumerated and their contents inspected, directory by directory. Large/truncated tool outputs were revisited with smaller line selections. Targeted searches covered process execution, credentials, environment loading, paths, installation commands, permissions, Actions references, and artifact publication.

- **Root:** `README.md` (usage, trust model, provider configuration, public-report caveats), `.env.example` (empty placeholders), `.gitignore` (environment-file exclusions), `.gitattributes` (shell line endings), and `LICENSE` (non-executable license text). The hidden `.git` entry is worktree metadata, not application source.
- **scripts/:** read all of `security-review.mjs`, `stream-summary.mjs`, `stream-summary.test.mjs`, `run-local.sh`, and `run-local.ps1`. Reviewed child environments, shell-free argument passing, Windows shim resolution, worktree creation/cleanup, timeout/error behavior, report and SARIF handling, commit/publication flow, and dotenv parsing. The dotenv wrappers parse assignments without evaluating or sourcing file contents. Also reviewed the new `security-boundaries.mjs` and its regression tests.
- **.github/workflows/:** read `security-review.yml` and `no-secrets.yml` in full. Reviewed triggers, matrix planning, secret selection, checkout credentials, CLI installs, Codex sandbox configuration, publishing privileges, SARIF upload, and log artifacts. These files remain byte-for-byte unchanged by this review.
- **examples/:** read `caller.yml` in full, including manual dispatch, write permissions, mutable reusable-workflow reference, and inherited secrets. It is a workflow template, not a running workflow in this repository. Its mutable reference is covered by SR-006.
- **extras/:** read `security-review.sh` and `single-repo-workflow.yml` in full despite their archived status. Reviewed all provider branches, inherited credentials, output paths, publication and cleanup, installation sources, checkout configuration, and artifacts. Minimal defensive fixes apply here as well. Mutable external tool references are covered by SR-006.

**Limits:** Git object history, external repositories, installed agent implementations, provider services, GitHub organization/repository policy, existing local credential stores, and dependencies downloaded at runtime were not fully audited. No package manifest or dependency lockfile exists in this repository; external CLIs are installed by workflows or supplied by the operator. No specific dependency CVE or upstream compromise is alleged. No real agents, provider calls, authenticated publication, commits, pushes, branches, or pull requests were run. Filesystem checks protect the publisher's post-agent operations; they are not a sandbox for the agents themselves and do not claim protection against a concurrently running process changing paths after validation.

### SR-001 — Known credential inheritance (CWE-522)

**Description:** `runCli` passed the complete publisher environment to every agent. Consequently `GH_TOKEN`/`GITHUB_TOKEN` and other providers' API keys could be exposed to an agent or its subprocesses even though only the publisher needs GitHub write access. The archived Bash runner inherited the same credentials.

**Impact:** Repository instructions, accidental tool use, or a compromised agent process could expose unrelated API credentials or obtain repository publishing authority. This issue requires access from within the reviewing process; no independent external endpoint is claimed.

**Change:** Added a tested environment boundary that removes the known GitHub, artifact-runtime, and provider credential variable names, case-insensitively, before restoring only the selected provider key and its trusted authentication overrides. The parent environment remains unchanged for publication. The archived runner now performs equivalent filtering in a subshell so its parent retains publishing credentials. This does not remove arbitrary operator-defined secrets, credential files, SSH agents, or credentials persisted in Git metadata; see SR-004.

### SR-002 — Unsafe report paths and artifact links (CWE-59)

**Description:** The publisher read the Markdown/SARIF paths without verifying that they were regular, non-symlink files. It also recursively created and moved reports through `REPORT_DIR` without checking for links or containment. A repository-supplied `security-reviews` directory link could redirect the publisher's operations outside its worktree. A linked input report could cause the publisher to read and publish unrelated local text if it satisfied the report-content check.

**Impact:** Unintended filesystem changes outside the worktree and potential disclosure of local file contents in the PR or SARIF export. The risk concerns the unsandboxed publishing stage, not just the agent's file permissions.

**Change:** Markdown and SARIF inputs must now be regular files. The report directory resolves inside the canonical worktree and each component must be a real directory, not a link or file, before creation/publication. The archived Bash runner rejects linked/non-regular reports, parent traversal/absolute destinations, and linked directory components. Tests cover nested directories, escape attempts, ordinary-file components, and Windows directory junctions. The file-symlink test is present but skipped on this host because Windows denied file symlink creation.

### SR-003 — Sensitive progress text (CWE-532)

**Description:** Failed result events printed `event.result`, retry events printed arbitrary `event.error`, and a Grep call without a path printed its search pattern. These free-form values can contain model findings, file snippets, or a literal credential being searched for; truncation and control-character removal do not redact sensitive content.

**Impact:** With streaming enabled, sensitive review content could appear in the public job log despite the documented promise not to print model text or file contents.

**Change:** Removed free-form result/error strings and omitted Grep patterns. Structured progress, HTTP status, timings, costs, tool names, explicit paths, and Glob patterns remain. Existing tests were updated and a regression test ensures sensitive values do not appear in these output channels. Raw private/local transcripts are unaffected; their workflow publication is separately tracked as SR-005.

### SR-004 — Persisted checkout credentials (CWE-522)

**Description:** The first `actions/checkout@v4` leaves `persist-credentials` at its enabled default. The caller grants contents/pull-request write access. Detached Git worktrees point back to the original repository metadata, which can expose the authentication configuration to a reviewing process. Removing `GH_TOKEN` from its environment alone does not close this second credential channel.

**Impact:** A repository-influenced reviewer can potentially obtain or use the checkout's write credential, undermining separation between reviewing and publishing.

**Status:** **Not fixed (workflow file)**. Exact fix: add `persist-credentials: false` to the first checkout. Configure `gh auth setup-git` with `GH_TOKEN` only for publisher-side Git authentication, rather than persisting an HTTP authorization header in the reviewed repository. Keep the token out of reviewer subprocess environments. The archived `extras/single-repo-workflow.yml` now implements the checkout opt-out and GitHub CLI credential helper; its helper obtains credentials from the publisher environment instead of embedding a token in Git metadata. This remains environment separation, not protection from arbitrary local credential stores.

### SR-005 — Raw transcript artifacts (CWE-200)

**Description:** The active workflow uploads `secreview-*/*.log` unconditionally, including full verbose streams containing model analysis and file/tool output. The README already acknowledges that artifacts and reports from public repositories are public; this warning does not restrict access or redact transcripts.

**Impact:** Raw transcripts can disclose newly found vulnerabilities, repository file contents, or secrets not recognized by GitHub's secret masking. SARIF privacy does not protect the parallel artifact channel.

**Status:** **Not fixed (workflow file)**. Exact fix: remove the raw `secreview-*/*.log` path from the artifact-upload step, retaining only the publisher's progress/status output, or make raw transcript export a clearly warned, explicitly opt-in mechanism restricted to appropriate private repositories. The archived workflow's raw transcript upload was removed. Report/PR visibility is still an intentional, documented product behavior; use a private repository for confidential review findings.

### SR-006 — Mutable execution dependencies (CWE-829)

**Description:** The reusable workflow installs `@anthropic-ai/claude-code` without an exact version, checks out its helper tool at a default `main` ref, and uses movable major-version tags for several Actions. The caller example also selects the reusable workflow at `main`, and the archived workflow similarly installs unversioned external CLIs and uses major Action tags. The Codex Action is already pinned to a full commit SHA.

**Impact:** An upstream tag/branch change or a compromised new package release can change privileged code executed during the next review without a reviewed change to the caller. This is a supply-chain exposure, not evidence that a particular release is malicious or vulnerable.

**Status:** **Not fixed (workflow file)** for the active reusable workflow. Exact fix: replace every movable Action reference with the full 40-character SHA of an owner-vetted release; pin both the reusable-workflow reference and `tool-ref` to the same audited commit; install an exact, tested CLI release with a checked-in dependency lock/integrity policy and reviewed updates. Apply the same policy to `examples/caller.yml` and `extras/single-repo-workflow.yml`. Those template references were not changed speculatively: a compatible, owner-vetted CLI/action release set is not established in this repository, and selecting the latest available versions would not establish compatibility or trust. Public upstream metadata was consulted, but external CLI packages and their transitive contents were not audited.

## Validation

- `node --test scripts/stream-summary.test.mjs scripts/security-boundaries.test.mjs`: 14 tests; 13 passed, zero failed, one Windows file-symlink test skipped. Directory-junction rejection passed.
- `node --check scripts/security-review.mjs`: passed.
- Git Bash `bash -n` on both Bash scripts: passed. The first attempt using the Windows WSL Bash launcher was denied; retried successfully using the installed Git Bash executable.
- Isolated Bash function checks for all three legacy provider branches: selected-provider authentication retained, unrelated provider/GitHub credentials absent, publisher environment unchanged.
- `git diff --check`: passed (only existing Git line-ending conversion warnings).
- SARIF structure, result/rule references, file paths, severity/status consistency, and protected-workflow non-modification checked before handoff.
